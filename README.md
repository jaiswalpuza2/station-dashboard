# Station

A real-time weather and markets dashboard styled as a meteorological instrument
panel — not another rounded-card weather app. Analog gauges, a compass needle,
and a graph-paper strip-chart recorder replace the usual grid of stat cards.
The same visual language extends to a stock watchlist panel: price-change dials
and mini strip-chart traces, not a table of green/red percentages.

No build step. No npm. Open it and it runs — and it's installable as a PWA.

## Running it

Browsers block `fetch()` from `file://` pages for security reasons, so don't
just double-click `index.html` — serve the folder over a local server instead
(one line, no install needed if you have Python or Node):

```bash
# Python 3
python3 -m http.server 8080

# or Node
npx serve .
```

Then open `http://localhost:8080` in your browser.

## PWA / offline support

Station is an installable Progressive Web App. When served over HTTPS (or
`localhost`), supporting browsers will show an install prompt. Once installed,
the app opens in its own window without browser chrome, and works offline using
the last-cached data.

**How the service worker works:**
- On install it precaches the static shell (HTML, CSS, all JS modules, icons,
  manifest) so the app opens instantly on repeat visits even without a network.
- API calls (Open-Meteo, Finnhub, Steam relay) use a **network-first** strategy:
  fresh data is always attempted; if the network fails, the most recently cached
  response for that exact URL is served instead so the panel shows the last
  known reading rather than a hard error.
- When a stale cached response is served, a small brass-bordered banner appears
  — "Showing the last reading — you're offline." — and disappears automatically
  once a live response comes back.

**Important: service workers only activate over HTTPS or `localhost`.**
Opening the project via a plain `http://` address (other than localhost /
127.0.0.1) will silently skip SW registration — all existing features still
work, you just don't get offline/install support. Once deployed to an HTTPS
domain (Vercel, Netlify, GitHub Pages, etc.) the install prompt appears
automatically in Chrome, Edge, and Safari on supported platforms.

**Regenerating the icons:**
The PWA icons (`assets/icon-192.png`, `assets/icon-512.png`) are generated by
`generate-icons.js` (no npm needed — pure Node built-ins). If you change the
brand colors, run:

```bash
node generate-icons.js
```

## What it does

### The Logbook

- **Auto-written event log** — a collapsible strip below the panel tabs,
  visible regardless of which track is active, that records notable moments
  as they happen across Weather, Markets, and Games.
- **Threshold-based rules, not AI commentary** — every entry is generated by
  a simple numeric comparison or state transition:
  - Weather: temperature changed ≥ 3 °C / 5 °F between polls; pressure dropped
    ≥ 2 hPa (rough storm signal); condition crossed into or out of precipitation.
  - Markets: a tracked stock crossed a round-dollar level ($50 increments) or
    moved ≥ 2% in a single polling interval.
  - Games: a tracked game hit a new player-count peak since tracking began
    (uses the existing peak-tracking logic — no duplication).
- **Ship's log voice** — plain, factual, present tense. "AAPL crossed $200."
  "Temperature dropped 4°C in the last interval." No exclamation points.
- **Collapsed by default** — shows the single most-recent entry as a one-line
  ticker; click to expand into a scrollable list of all entries (newest first).
  Each entry has a small colored track tag (brass = weather, blue = markets,
  moss = games), a timestamp, and the message.
- **Persisted in localStorage** — survives reloads; capped at 50 entries,
  oldest evicted first. A clear button is accessible on hover.

### Weather panel

- **Geolocation on first visit** — on a fresh load with no stored place, the
  panel requests your browser's location and uses it immediately. If permission
  is denied, unavailable, or times out, it falls back silently to the default
  station (Kathmandu) and shows a small dismissible note explaining why — no
  browser-style `alert()`.
- **Search** any place by name (Open-Meteo's geocoding API) with debounced
  autocomplete and full keyboard navigation (↑ / ↓ / Enter / Esc).
- **Live conditions** — temperature, feels-like, humidity, wind (speed +
  direction), pressure, precipitation — rendered as analog instrument dials.
- **24-hour temperature trace** drawn on a canvas strip-chart styled like an
  old paper recorder.
- **7-day forecast** rail with hand-drawn condition glyphs (no emoji).
- **Metric / imperial toggle**, remembered across visits.
- **Auto-refresh** every 5 minutes; last-searched place restored on reload.

### Games panel

- **Live Steam player counts** — tracks concurrent players for any Steam game
  using the `GetNumberOfCurrentPlayers` endpoint, routed through a self-hosted
  Cloudflare Worker relay (Steam's API has no CORS support for browser calls —
  see "Setting up the Games panel" below).
- **Instrument-panel dial per game** — the needle shows the current count
  against the rolling session peak (tracked in `localStorage` per appid and
  raised whenever a new high arrives, persisted across reloads).
- **6-hour strip-chart trace per game** — player counts are sampled every
  5 minutes and stored in a rolling `localStorage` buffer so the chart has
  history across reloads rather than starting empty every visit.
- **Editable watchlist** — search by game name (Steam store autocomplete) or
  paste a raw Steam appid directly; add/remove persisted in `localStorage`.
  Falls back to a hardcoded popular-games list if the autocomplete endpoint
  is unavailable. Defaults to CS2, Dota 2, PUBG, Apex Legends.
- **Independent polling** — games poll every 5 minutes, independent of
  weather (5 min) and markets (1 min).

### Markets panel

- **Instrument-panel stock watchlist** — each ticker gets a dial face showing
  price-change percentage (±10% range, green/red/brass coloring) and a mini
  strip-chart of the last 30 days of closing prices.
- **Editable watchlist** — add or remove symbols via an input in the panel
  header; persisted in `localStorage`. Defaults to AAPL, MSFT, TSLA, AMZN.
- **Independent polling** — market data refreshes every 60 seconds, weather
  every 5 minutes; neither blocks the other.
- **Graceful rate-limit handling** — Finnhub's 429 response is a first-class
  `StationError` kind (`'rate-limit'`), worded as "the ticker tape jammed"
  rather than a generic error. `Promise.allSettled` ensures one bad symbol
  does not blank the whole panel.
- **Price history via poll snapshots** — the strip-chart traces are built from
  successive `/quote` poll results stored in `localStorage` under
  `station:price-history`. Each 60-second poll appends a point; the trace
  fills in over time (up to 60 points, ~1 hour of intraday history per session).
  This sidesteps the CORS restrictions of every free history endpoint: Stooq
  blocks browser fetches, Yahoo Finance does too, and Finnhub's `/stock/candle`
  is 403 on the free tier. The trade-off is explicit: the trace is sparse on
  first load and honest about it ("building trace…").
- **No-key state** — if you haven't added a Finnhub key yet, the panel shows
  a friendly setup prompt rather than crashing.

### Interface

- **Weather / Markets / Games tab switcher** in the header — no page reload, no scroll.
  The place-search form hides automatically when the weather panel is not active.
- **Dark / light instrument-panel variants** — toggled by a button in the
  footer of each panel. Not a generic color-invert: the light theme is a
  brass panel in daylight (aged parchment surfaces, dark-ink readouts, richer
  brass) vs. the dark theme's observatory backdrop. Both keep the gauge faces,
  strip-chart paper texture, and dial language intact.
  - Defaults to your OS preference (`prefers-color-scheme`) on first visit.
  - Persisted in `localStorage` under `station:theme`.
  - The canvas strip-charts re-read CSS custom properties at draw time so they
    always match the active theme without a second fetch.
- **Typed error handling** throughout — `StationError` kinds (`network`,
  `not-found`, `bad-response`, `malformed`, `geo-denied`, `geo-unavailable`,
  `geo-timeout`, `rate-limit`, `no-key`) are each worded differently rather
  than showing a generic "error" toast. See `js/api.js` and `js/markets-api.js`.

## Setting up the games panel

Steam's `GetNumberOfCurrentPlayers` API does not send CORS headers, so direct
browser fetches are blocked by the browser's same-origin policy. The Games
track routes these requests through a Cloudflare Worker that calls Steam
server-side and re-serves the response with the correct headers.

The deployed Worker at `https://steam-relay.kavitachy702.workers.dev/` is
tied to one Cloudflare account. If you fork this project, deploy your own:

1. Sign up at <https://workers.cloudflare.com> (free tier is sufficient).
2. Create a new Worker and paste this code:

```js
export default {
  async fetch(request) {
    const appid = new URL(request.url).searchParams.get('appid');
    if (!appid || !/^\d+$/.test(appid)) {
      return new Response(JSON.stringify({ error: 'missing appid' }), { status: 400 });
    }
    const upstream = `https://api.steampowered.com/ISteamUserStats/GetNumberOfCurrentPlayers/v1/?appid=${appid}`;
    const res = await fetch(upstream);
    const body = await res.text();
    return new Response(body, {
      status: res.status,
      headers: {
        'Content-Type': 'application/json',
        'Access-Control-Allow-Origin': '*',
      },
    });
  },
};
```

3. Deploy it and update `STEAM_RELAY_URL` in `js/games-api.js` to point to
   your Worker's URL.

## Setting up the markets panel

The markets panel requires a free Finnhub API key:

1. Sign up at <https://finnhub.io/register> (free, no credit card).
2. Copy `js/config.example.js` → `js/config.js`.
3. Paste your key into the `FINNHUB_API_KEY` value in `js/config.js`.

`js/config.js` is gitignored — your key stays local. The weather panel works
without any key; only the markets panel is gated.

**Rate limit:** Finnhub's free tier allows 60 API calls per minute. With a
5-symbol watchlist the panel uses ≤ 5 calls per refresh, well within the limit
during a normal session. The app backs off automatically on a 429 response.

## Why it looks like this

The design brief was "premium, unique, not something anyone's seen before."
Rather than the default warm-serif-and-terracotta or dark-mode-with-neon-
accent look most generated dashboards land on, this one is grounded in what
the subject actually is: a weather *station*. That gave a legitimate reason
to reach for analog gauges, brass/glass tones, and monospace instrument
readouts — real meteorological hardware, not decoration.

The light theme extends the same logic: a brass instrument panel lit by
daylight rather than observed in a darkened room. Aged parchment replaces
lacquered oak; the brass accent reads richer and warmer; dark-ink readouts
replace the luminous white text. The gauges don't change — only the cabinet
around them.

The one deliberate motion moment is the gauge needles sweeping into place on
load; everything else stays quiet.

                           snapshot store (localStorage)

                           history + peak store (localStorage); game search
js/logbook.js            Auto-written event log; threshold rules for all three
                           tracks; localStorage store (capped at 50 entries)

## Data sources

- **Weather:** [Open-Meteo](https://open-meteo.com) — free, no API key,
  CORS-enabled. Endpoints: `/v1/forecast` and `/v1/search`.
- **Markets:** [Finnhub](https://finnhub.io) — free tier (key required),
  60 calls/minute. Endpoint: `/api/v1/quote` (live price + % change).
  Price history accumulated from poll snapshots in `localStorage`.
- **Games:** [Steam Web API](https://partner.steamgames.com/doc/webapi) —
  free, no key required. Routed through a self-hosted Cloudflare Worker relay
  because Steam's API blocks direct browser fetches (no CORS headers).
  Game search via Steam store suggest (`store.steampowered.com/search/suggest`).
  Player-count history accumulated from poll snapshots in `localStorage`.

## localStorage keys

| Key | What it stores |
|---|---|
| `station:last-place` | Last searched weather location |
| `station:unit` | `"metric"` or `"imperial"` |
| `station:theme` | `"dark"` or `"light"` |
| `station:watchlist` | JSON array of stock ticker symbols |
| `station:panel` | `"weather"`, `"markets"`, or `"games"` (last active panel) |
| `station:price-history` | Rolling price snapshots per symbol (up to 60 points each) |
| `station:games-list` | JSON array of `{ appid, name }` objects |
| `station:games-history` | Rolling player-count snapshots per appid (last 6 hours) |
| `station:games-peak` | Session peak player count per appid |
